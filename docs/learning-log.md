# Learning log

Concepts explained while building this site, one entry per concept. Claude appends here at the end
of each step. Later, good entries become blog posts.

Format:
- **YYYY-MM-DD, step X.Y, Concept:** one-sentence explanation. *Analogy:* … *Source:* link (optional)

---
- **2026-10-08, step 0.1, Static site generation:** Hugo merges Markdown (`content/`) into templates (`layouts/`) once, at build time, and writes plain files to `public/`; the server only hands files out. *Analogy:* a bakery bakes everything at 6 a.m. instead of a restaurant cooking each order.
- **2026-10-08, step 0.1, make:** a Makefile gives long commands short names (`make check`), so laptop, CI and Claude run the identical thing. *Analogy:* ordering "number 3" from a menu; the kitchen knows the recipe.
- **2026-10-08, step 0.1, Version pinning:** `versions.env` fixes the exact Hugo version for laptop and CI, so "works on my machine" means "works in CI". *Analogy:* a recipe naming the exact flour brand.
- **2026-10-08, step 0.1, Checksums / trust on first use:** a SHA-256 is a file's fingerprint; pinning it in the repo makes the installer refuse any download that differs (tested with a fake hash: exit 1, nothing unpacked). Same model as SSH host keys or `go.sum`. *Analogy:* checking the medicine's tamper seal against the number you wrote down when ordering. *Source:* docs/decisions/0006-pin-tool-checksums.md
- **2026-10-08, step 0.1, Behaviour-preserving refactor:** fixing a deprecation should change code, not output; proved by diffing `public/` before and after (`diff -r` → identical). *Analogy:* replacing a worn pipe without changing the water pressure.
- **2026-10-08, step 0.1, Baseline commit:** commit the untouched starting point first so the next commit's diff shows exactly what changed. *Analogy:* the "before" photo before a renovation.
- **2026-10-08, step 0.1, Commit email privacy:** commits are public forever once pushed; a GitHub no-reply address (`<id>+user@users.noreply.github.com`, set repo-local in `.git/config`) still links them to the profile. *Analogy:* a PO box on public mail.
- **2026-10-08, research, Round trips and connection reuse:** a first visit pays DNS + connection + TLS + request (3–4 round trips, ~130 ms each to the US); later pages reuse the open connection (1 round trip). HTTP/3 (QUIC) merges connection and TLS setup. *Analogy:* dialling and "hello, who's this?" happen once per call, not per question. *Source:* docs/research/2026-10-stack-review.md
- **2026-10-08, research, CDN trade-off:** a CDN puts copies near visitors; for ~1.5 KB pages the US penalty from Warsaw (~0.25–0.5 s first view) stays far under the 2.5 s LCP budget, so no CDN at launch. *Analogy:* corner shops worldwide vs one warehouse in Warsaw. *Source:* ADR 0005, research doc.
- **2026-10-08, research, 14 KB rule:** TCP and QUIC send only ~14 KB before waiting for the first acknowledgement (RFC 9002 §7.2), so a page that fits arrives in one burst; it's a guide, not a cliff. *Analogy:* the first delivery van has a fixed size; anything extra waits for the second trip.
- **2026-10-08, step 0.2, Continuous integration:** every push runs the same `make check` on a fresh GitHub machine, so leftovers on the laptop can't hide a broken build; the badge shows the latest result on `main`. *Analogy:* a building inspector checking every change against the same rulebook, on an empty lot each time.
- **2026-10-08, step 0.2, Pinning actions by SHA:** `uses: actions/checkout@v7` follows a tag the owner can move; a full commit SHA can't be changed, so the code we reviewed is the code that runs. Dependabot opens PRs to bump the SHA. *Analogy:* hiring a named inspector, not "whoever shows up with a v7 badge".
- **2026-10-08, step 0.2, Least privilege in CI:** `permissions: contents: read` and `persist-credentials: false` mean the build job holds no token that could push or change the repo. *Analogy:* the inspector gets a visitor badge, not the master key.
- **2026-10-08, step 0.2, Reading the source beats guessing:** an "unverified" worry (comments in `$GITHUB_ENV`) was settled by reading the runner's open-source parser (FileCommandManager.cs): any line without `=` or `<<` throws `Invalid format`. *Analogy:* checking the rulebook instead of asking around.
- **2026-10-08, step 0.2, Reproducible builds:** the CI artifact matched the local build byte-for-byte except the build-SHA meta tag, which equals the pushed commit; that tag becomes the deploy smoke test in 1.4. *Analogy:* two bakeries, same recipe and flour, identical loaves; only the date stamp differs.
- **2026-10-08, step 0.2, Licensing:** public code without a license is "look, don't touch"; MIT for code + CC BY 4.0 for writing lets others reuse snippets while posts keep attribution. *Source:* docs/decisions/0007-licensing.md
- **2026-10-08, design, Contrast ratio:** WCAG compares the relative brightness of text and background; normal text needs at least 4.5:1. Measure the real background (a tinted row is darker than the page): amber passed on the page (5.2:1) but failed on the violet-tinted row (4.47:1). *Analogy:* reading a sign depends on the wall it hangs on, not just the paint. *Source:* docs/design-spec.md
- **2026-10-08, design, One token, two values:** design systems give each theme its own value for the same role (`--accent` = yellow in dark, violet in light), because a colour that shines on black can look muddy on white even when it passes contrast. *Analogy:* the same street sign uses reflective paint at night and plain paint by day.
- **2026-10-08, design, Font subsets and lazy font loading:** Google Fonts splits a font into `latin` and `latin-ext` files with `unicode-range`; the browser downloads only the files whose characters appear on the page, and a font that no text uses is never fetched. So English pages skip the Polish file and pages without code skip JetBrains Mono. *Analogy:* a restaurant brings the dessert menu only to tables that ask for dessert.
- **2026-10-08, design, Spotlight with :has():** `.list:has(a:hover) a:not(:hover) { opacity: .32 }` dims every row except the one under the pointer, in pure CSS; gate it with `@media (hover: hover)` and mirror it with `:focus-visible` for keyboards. *Analogy:* a stage light that follows the speaker while the rest of the stage goes dim.
- **2026-10-08, design, Icons need labels:** NN/g's icon research says icons alone are ambiguous; a visible text label (not just a tooltip) makes them findable. That is why the theme switch shows the word LIGHT / DARK next to the eclipse. *Source:* https://www.nngroup.com/articles/icon-usability/
- **2026-10-09, step 0.3, Registrar vs DNS host:** the registrar rents you the name (Cloudflare Registrar, until 2027-10-08); the DNS host answers "where is it?" (Cloudflare DNS). They can be different companies. RDAP shows the public registration data. *Analogy:* the land registry vs the street signs.
- **2026-10-09, step 0.3, A / AAAA / TTL:** A gives an IPv4, AAAA an IPv6 address; TTL 300 lets resolvers cache the answer 5 minutes, so a server move reaches everyone within ~5 minutes. Checked three ways: 1.1.1.1, 8.8.8.8 and the zone's own nameserver. *Analogy:* a phone book entry with a "valid for" date.
- **2026-10-09, step 0.3, Cloudflare proxy (orange cloud):** on by default; DNS then returns Cloudflare's IPs (188.114.x.x) instead of the server's, putting a CDN in front. Turned off (grey, DNS only) per ADR 0005 so Caddy gets its own certificates and real visitor IPs. *Analogy:* a receptionist who takes every call for you.
- **2026-10-09, step 0.3, Negative caching:** a resolver also caches "this record doesn't exist", so a new record can appear later on some resolvers than on others. *Analogy:* a friend who checked yesterday and still believes the shop is closed.
- **2026-10-09, step 0.3, Email authentication:** MX says where mail for the domain goes (lower priority number first); SPF lists who may send; DKIM signs messages; DMARC tells receivers what to do with mail that fails both (`p=reject`). A domain that never sends mail publishes a null MX (`0 .`), `v=spf1 -all` and `p=reject`. *Analogy:* a return address, a wax seal, and a note to the post office to destroy letters without the seal.
- **2026-10-09, step 0.3, SSH host key check (TOFU, out-of-band):** the first SSH connection shows the server's fingerprint; comparing it with the one read on the provider's KVM console proves no one is in the middle before you send a password. A low-res screenshot misread `l` as `1`, which is why you compare against the source. *Analogy:* checking a caller's face on a video call before telling them a secret.
- **2026-10-09, step 0.3, Public key login:** `ssh-copy-id` hangs your public key (a padlock) in `~/.ssh/authorized_keys`; logging in proves you hold the private key without sending it. A stolen padlock opens nothing; the danger is someone writing their own padlock into the file, so sshd refuses loose permissions (`StrictModes`) and SELinux needs the `ssh_home_t` label. *Analogy:* handing the doorman an open padlock only your key fits.
- **2026-10-09, step 0.3, Effective config and drop-in order:** `sshd -T` prints the settings sshd will really use; files in `sshd_config.d/` are read alphabetically and the first value wins, so `01-no-passwords.conf` beats cloud-init's `50-cloud-init.conf`. Test with `sshd -t` before `reload`, then prove it from outside (password login refused, key login works). *Analogy:* the final bill vs the menu.
- **2026-10-09, step 0.3, Bots arrive within hours:** the first failed SSH login came from an unknown IP hours after the VPS went online; internet-wide scanners try every SSH port they find, which is why password logins were turned off the same day. *Analogy:* people trying door handles along a busy street.
- **2026-10-09, step 1.1, baseof + blocks:** `baseof.html` is the shared frame (`<html>`, header, footer); `{{ block "main" . }}` is a hole that each page template (`home.html`, `list.html`, `single.html`) fills with `{{ define "main" }}`. *Analogy:* one picture frame, a different picture per page.
- **2026-10-09, step 1.1, Partials:** `{{ partial "post-meta.html" . }}` pastes a reusable snippet; the `.` hands it the current page, so inside the partial `.Date` means that page's date. *Analogy:* a rubber stamp you ink with whatever page you're on.
- **2026-10-09, step 1.1, Lookup order:** Hugo picks the most specific template that exists (e.g. a section-specific one before `single.html`), so adding a file can change a page without touching the old one. *Analogy:* a waiter checking for a table's special dish before serving the house dish.
- **2026-10-09, step 1.1, .Pages vs site.RegularPages:** `.Pages` is the direct children of the current page (a section's posts, the home page's sections); `site.RegularPages` is every content page on the site, so the home page filters it with `where … "Section" "blog"` to list posts. *Analogy:* the books on one shelf vs the library's whole catalogue.
- **2026-10-09, step 1.1, Dates from git:** with `enableGitInfo`, `.Lastmod` is the date of the last commit touching the file. CI's default checkout is one commit deep, which would make every post "updated today", so CI needs `fetch-depth: 0`. *Analogy:* asking the archive when a document last changed; a photocopy of only today's page can't answer.
- **2026-10-09, step 1.1, Show only what applies:** each meta item appears only when its data exists, and `ne .Params.showUpdated false` treats a missing field as "show" so only an explicit `false` hides it; tested missing / false / true. *Analogy:* automatic headlights with a manual off switch.
- **2026-10-09, step 1.1, Check the evidence before copying a pattern:** reading-time labels are everywhere, but the claimed engagement gains come from marketing anecdotes and none of the exemplar sites use them, so the slot shows "updated" and "tested on" instead. *Analogy:* not buying a gadget just because every shop window has one.
- **2026-10-10, step 1.2, Design tokens with light-dark():** each colour is a role (`--ink`, `--accent`) written once as `light-dark(light, dark)`; the page's `color-scheme` picks the side (OS by default, `data-theme` when the user chooses). *Analogy:* a reversible jacket; which side faces out depends on the weather.
- **2026-10-10, step 1.2, Self-hosted fonts with unicode-range:** `@font-face` only declares a font; the browser downloads a file when text uses that family *and* contains characters in its range, so English pages never fetch Polish or Cyrillic files. Files pinned by SHA-256 like the build tools (ADR 0009). *Analogy:* a warehouse that ships a box only when an order needs what's inside.
- **2026-10-10, step 1.2, No-flash theme:** a tiny inline script in `<head>` (before the CSS) applies the saved theme before the first paint; the switch label is pure CSS (all three words in the HTML, one shown), so it is right from the first frame. Without JavaScript the switch hides and the OS decides. *Analogy:* setting the stage lights before the curtain opens, not after.
- **2026-10-10, step 1.2, View Transitions:** `document.startViewTransition(change)` snapshots the old page, applies the change, and lets CSS/JS animate between the two; here a growing circle from the button. Skipped when nothing visible changes or motion is reduced. *Analogy:* a photographer taking before/after shots and sliding one over the other.
- **2026-10-10, step 1.2, Honest UI:** the build strip shows only facts true at build time (sha, origin, Hugo version, "checks passed" only on CI builds); "0 KB JavaScript" left the footer once it stopped being true. *Analogy:* a dashboard that shows sensor readings, not painted-on needles.
- **2026-10-10, step 1.2, Hugo skips future-dated pages:** `date: 2026-10-10` means midnight UTC; just after midnight in Kraków it was still 9 October in UTC, so Hugo treated the page as unpublished (`buildFuture` is off). *Analogy:* a newspaper that won't print tomorrow's edition early.
- **2026-10-10, step 1.2, Verify visually, not only by build:** headless Firefox screenshots (`--screenshot`, a throwaway profile with `ui.systemUsesDarkTheme`) caught what `make check` can't: misaligned rows, a white scrollbar on dark code, a squeezed table, an empty heading in a language without posts. *Analogy:* a test drive after the factory checks.
- **2026-10-10, step 1.3, Idempotency:** a playbook describes the end state; running it again on a server already in that state changes nothing (`changed=0`). *Analogy:* a thermostat set to 21 °C does nothing in a 21 °C room, while "heat for 10 minutes" would overheat it on the second run.
- **2026-10-10, step 1.3, Verify a download by an independent route:** a checksum fetched from the same server only catches corruption; AlmaLinux's *signature* on the checksum list, checked with a key that arrived through Fedora's own signed package (`distribution-gpg-keys`), proves the list is authentic. *Analogy:* checking a passport against the issuing country's database, not against a photocopy the traveller brought.
- **2026-10-10, step 1.3, Cloud images + cloud-init:** a generic disk image plus a small first-boot instruction file (user, key, hostname) is how cloud VPSes are made; the lab VM was built the same way as the OVH server, so it starts in the same state. *Analogy:* the same flat-pack furniture and the same assembly sheet, delivered to a different house.
- **2026-10-10, step 1.3, qcow2 overlays:** a thin disk that records only changes on top of an untouched base image; deleting it resets the VM to factory-fresh in seconds without re-downloading. *Analogy:* tracing paper over a printed map.
- **2026-10-10, step 1.3, libvirt as the mail slot:** `virsh vol-upload` hands a file to libvirtd (running as root) which stores it in `/var/lib/libvirt/images` with the right SELinux label, so no sudo is needed. In ESXi terms: libvirt ≈ hostd, virbr0 ≈ a private vSwitch, the pool ≈ a datastore. *Analogy:* pushing a package through the slot of a locked room; the clerk inside files it.
- **2026-10-10, step 1.3, Where Ansible finds group_vars:** `ansible-playbook` loads `group_vars/` only next to the inventory file or the playbook; a folder anywhere else is silently ignored (the skeleton's was, `site_domain=UNDEFINED`). `group_vars/all/` as a folder loads every file inside, which is how `vars.yml` and `secrets.vault.yml` live side by side. *Analogy:* mail delivered to the address on the envelope, not to the house next door.
- **2026-10-10, step 1.3, `!` in a terminal:** in bash, `! cmd` inverts the exit status, so `! a && b` never runs `b`. (At Claude Code's prompt `!` means "run in a shell".) *Analogy:* a "NOT" sign stuck in front of a green light.
- **2026-10-10, step 1.3, ok vs changed:** each Ansible task compares what the role wants with what the server has; equal = `ok`, different = `changed`. Predicting needs both sides visible (the role's settings and a command showing the server's state); without them it's guessing. *Analogy:* a checklist inspector compares the spec sheet with the room, item by item.
- **2026-10-10, step 1.3, Dry runs pretend:** `--check` changes nothing, so a task that depends on an earlier step (a timer shipped inside a package that was only "pretend-installed") fails in a dry run of a fresh server. The fix skips only that case (`when: not (ansible_check_mode and pkg is changed)`); `ignore_errors` would also hide real failures. *Analogy:* you can rehearse hanging a picture, but not straightening one that was never hung.
- **2026-10-10, step 1.3, Hostname vs DNS:** the hostname is the server's own name (prompt, logs); visitors find the server through DNS (A record → IP). *Analogy:* the nameplate on an office door vs the street address on the city map.
- **2026-10-10, step 1.3, Automatic security updates:** a fresh AlmaLinux image already had 53 pending security notices (32 Important). `dnf-automatic` with `upgrade_type = security`, `apply_updates = yes` installs only security fixes daily; `reboot = when-needed` reboots only when a kernel/core-library fix requires it (~30-60 s downtime). *Analogy:* a night cleaner who briefly closes the restaurant only when the floor really needs it.
- **2026-10-10, step 1.3, The recap counts tasks:** `changed=4` with five changed lines, because a looped task (three lines of one file) counts once. *Analogy:* one work order with three items is still one order.
- **2026-10-10, step 1.3, Changing the locks while inside:** a two-phase bootstrap avoids locking yourself out: run 1 (as the image's user) creates `kai` and hardens SSH but keeps the old user allowed; only after testing that `kai` logs in and sudo works does run 2 (as `kai`) remove the old user's access. *Analogy:* hand yourself the new key and try it before the old lock is removed.
- **2026-10-10, step 1.3, Handlers:** a handler (e.g. "reload sshd") runs only when a task that notifies it reports `changed`; `meta: flush_handlers` runs pending handlers at that point instead of at the end. `reload` re-reads config without dropping SSH sessions. *Analogy:* the waiter announces menu changes only when something on the menu changed.
- **2026-10-10, step 1.3, ok vs skipping:** `skipping` appears only when a `when:` condition is false; a task without a condition that finds nothing to do reports `ok`. *Analogy:* "not my shift" (skipped) vs "came in, everything was already done" (ok).
- **2026-10-10, step 1.3, Ansible Vault:** secrets live in an AES-encrypted file committed to Git (`secrets.vault.yml`); the key to open it (`.vault_pass`, chmod 600, gitignored) stays on the desktop and in KeePassXC. Only a salted SHA-512 hash of kai's sudo password reaches the server; `no_log` keeps it out of output. *Analogy:* a locked safe can sit in a shared office; only the combination must stay private.
- **2026-10-10, step 1.3, Key + password:** SSH accepts only kai's key, and sudo still asks for kai's password, so a stolen key alone doesn't give root. *Analogy:* a door key plus an alarm PIN.
- **2026-10-10, step 1.3, ansible.cfg comments:** a `#` after a value in `ansible.cfg` becomes part of the value (`.vault_pass   # note` was read as the file name); comments go on their own line. *Analogy:* writing a note inside the address field of an envelope.
- **2026-11-27, refresh, A config line that does nothing:** `result_format = yaml` sat in `ansible.cfg` for weeks and changed nothing; Ansible ignores keys it doesn't know without a word (the real key is `callback_result_format`). A silently ignored line is worse than an error, so ask the tool what it read: `ansible-config dump --only-changed -t all`. *Analogy:* a light switch wired to nothing; look at the lamp, not at the switch.
- **2026-11-27, refresh, Facts in one drawer:** Ansible stores what it learns about a server in the `ansible_facts` dictionary and, by old habit, also copies each fact into a top-level `ansible_*` variable. `inject_facts_as_vars = False` stops the copying (the default flips in ansible-core 2.24), so roles use `ansible_facts['distribution']`. *Analogy:* papers kept in one labelled drawer instead of also lying loose on the desk, where they get mixed up with your own notes.
- **2026-11-27, refresh, Rehearse an upgrade:** before changing the pin, the candidate Hugo built the site into a scratch folder and `diff -r` compared it with the pinned build; only the version string differed. `--panicOnWarning` turns deprecations (`.IsNode` since 0.163, `.Params.title` since 0.169) into failed builds. *Analogy:* baking one test tray in the new oven before moving the whole bakery over.
- **2026-11-27, refresh, Permission rules: first list wins:** Claude Code checks `deny`, then `ask`, then `allow`, and how specific a rule is doesn't matter; an exact command in `allow` still prompts while a wider pattern for it sits in `ask`. Cloud IAM policies work the same way (an explicit deny beats any allow). *Analogy:* the doorman checks the banned list, then the "call the manager" list, and only then the guest list.
- **2026-11-27, refresh, Research goes stale too:** a month-old plan was right on facts but half of it described a repo that no longer existed; every claim was re-checked against the repo and upstream before any change. Local tests rank above release notes, release notes above web pages. *Analogy:* checking the pantry before shopping from last month's list.
- **2026-11-27, practices review, Staging part of a file:** git's staging area (the index) holds its own copy of each file, so a commit can take some changes from a file and leave others on disk; today's refresh commit took 48 lines and left the older edits uncommitted. *Analogy:* a photocopy with some paragraphs covered goes into the envelope; the original stays on the desk.
- **2026-11-27, practices review, A question needs its ingredients first:** a check question teaches when what it needs was shown before it and the answer follows it; a cold question is a blind guess. Watching alone is weak too: students who picked an outcome before a demonstration learned more than those who only watched, though only 26% picked right. *Analogy:* tasting the dish and being asked "more salt or less?" works; being asked for the recipe before you have tasted it doesn't. *Source:* docs/research/2026-11-practices-review.md
- **2026-11-27, practices review, The strict build had a hole:** a template key that exists in no language file printed an empty string and passed `--panicOnWarning`; Hugo only warns about it with `--printI18nWarnings`. Our own checker compared the language files with each other, never with the templates. *Analogy:* checking that three phone books list the same names, but never whether the person you are calling is in any of them.
- **2026-11-27, practices review, Imports don't save context:** `@file` in CLAUDE.md loads the whole file into every session, so a growing roadmap costs tokens each time; a plain pointer ("read docs/roadmap.md when planning") loads it only when needed. *Analogy:* carrying the whole binder to every meeting versus knowing which shelf it is on.
- **2026-11-27, practices review, Where a deny rule is anchored:** `Read(./path)` is resolved from the current directory, `Read(/path)` from the project root; after `cd infra/ansible` a `./infra/ansible/…` rule pointed at nothing. Secret rules are now written both ways. *Analogy:* "second door on the left" depends on where you stand; a room number doesn't.
- **2026-11-27, practices review, Why a tool that suits big repos doesn't suit this one:** Graphify builds a map of a codebase so an assistant reads less; with 113 files, most of them prose and YAML, there is little to save, while its installer adds hooks to every file read and upgrades itself unpinned. *Analogy:* hiring a librarian with a card catalogue for a single bookshelf.
- **2026-11-27, practices review, DNSSEC:** plain DNS answers carry no proof of origin, so a forged answer looks like a real one. DNSSEC signs the zone's records, and a fingerprint of the signing key (the DS record) is published one level up, at `.dev`, so a resolver can check the chain. Off for this domain on 2026-11-27 (`dig +short DS vadymherman.dev` printed nothing). *Analogy:* a wax seal on a letter, with a copy of your seal kept at the post office to compare against.
