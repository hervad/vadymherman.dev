# Learning log

Concepts explained while building this site, one entry per concept. Claude appends here at the end
of each step. Later, good entries become blog posts.

Format:
- **YYYY-MM-DD, step X.Y, Concept:** one-sentence explanation. *Analogy:* … *Source:* link (optional)

---
- **2026-10-08, step 0.1, Static site generation:** Hugo merges Markdown (`content/`) into templates (`layouts/`) once, at build time, and writes plain files to `public/`; the server only hands files out. *Analogy:* a bakery bakes everything at 6 a.m. instead of a restaurant cooking each order.
- **2026-10-08, step 0.1, make:** a Makefile gives long commands short names (`make check`), so laptop, CI and Claude run the identical thing. *Analogy:* ordering "number 3" from a menu; the kitchen knows the recipe.
- **2026-10-08, step 0.1, Version pinning:** `versions.env` fixes the exact Hugo version for laptop and CI, so "works on my machine" means "works in CI". *Analogy:* a recipe naming the exact flour brand.
- **2026-10-08, step 0.1, Checksums / trust on first use:** a SHA-256 is a file's fingerprint; pinning it in the repo makes the installer refuse any download that differs (tested with a fake hash: exit 1, nothing unpacked). Same model as SSH host keys or `go.sum`. *Analogy:* checking the medicine's tamper seal against the number you wrote down when ordering. *Source:* docs/decisions/0006-pin-tool-checksums.md
- **2026-10-08, step 0.1, Behaviour-preserving refactor:** fixing a deprecation should change code, not output; proved by diffing `public/` before and after (`diff -r` → identical). *Analogy:* replacing a worn pipe without changing the water pressure.
- **2026-10-08, step 0.1, Baseline commit:** commit the untouched starting point first so the next commit's diff shows exactly what changed. *Analogy:* the "before" photo before a renovation.
- **2026-10-08, step 0.1, Commit email privacy:** commits are public forever once pushed; a GitHub no-reply address (`<id>+user@users.noreply.github.com`, set repo-local in `.git/config`) still links them to the profile. *Analogy:* a PO box on public mail.
- **2026-10-08, research, Round trips and connection reuse:** a first visit pays DNS + connection + TLS + request (3–4 round trips, ~130 ms each to the US); later pages reuse the open connection (1 round trip). HTTP/3 (QUIC) merges connection and TLS setup. *Analogy:* dialling and "hello, who's this?" happen once per call, not per question. *Source:* docs/research/2026-10-stack-review.md
- **2026-10-08, research, CDN trade-off:** a CDN puts copies near visitors; for ~1.5 KB pages the US penalty from Warsaw (~0.25–0.5 s first view) stays far under the 2.5 s LCP budget, so no CDN at launch. *Analogy:* corner shops worldwide vs one warehouse in Warsaw. *Source:* ADR 0005, research doc.
- **2026-10-08, research, 14 KB rule:** TCP and QUIC send only ~14 KB before waiting for the first acknowledgement (RFC 9002 §7.2), so a page that fits arrives in one burst; it's a guide, not a cliff. *Analogy:* the first delivery van has a fixed size; anything extra waits for the second trip.
- **2026-10-08, step 0.2, Continuous integration:** every push runs the same `make check` on a fresh GitHub machine, so leftovers on the laptop can't hide a broken build; the badge shows the latest result on `main`. *Analogy:* a building inspector checking every change against the same rulebook, on an empty lot each time.
- **2026-10-08, step 0.2, Pinning actions by SHA:** `uses: actions/checkout@v7` follows a tag the owner can move; a full commit SHA can't be changed, so the code we reviewed is the code that runs. Dependabot opens PRs to bump the SHA. *Analogy:* hiring a named inspector, not "whoever shows up with a v7 badge".
- **2026-10-08, step 0.2, Least privilege in CI:** `permissions: contents: read` and `persist-credentials: false` mean the build job holds no token that could push or change the repo. *Analogy:* the inspector gets a visitor badge, not the master key.
- **2026-10-08, step 0.2, Reading the source beats guessing:** an "unverified" worry (comments in `$GITHUB_ENV`) was settled by reading the runner's open-source parser (FileCommandManager.cs): any line without `=` or `<<` throws `Invalid format`. *Analogy:* checking the rulebook instead of asking around.
- **2026-10-08, step 0.2, Reproducible builds:** the CI artifact matched the local build byte-for-byte except the build-SHA meta tag, which equals the pushed commit; that tag becomes the deploy smoke test in 1.4. *Analogy:* two bakeries, same recipe and flour, identical loaves; only the date stamp differs.
- **2026-10-08, step 0.2, Licensing:** public code without a license is "look, don't touch"; MIT for code + CC BY 4.0 for writing lets others reuse snippets while posts keep attribution. *Source:* docs/decisions/0007-licensing.md
- **2026-10-08, design, Contrast ratio:** WCAG compares the relative brightness of text and background; normal text needs at least 4.5:1. Measure the real background (a tinted row is darker than the page): amber passed on the page (5.2:1) but failed on the violet-tinted row (4.47:1). *Analogy:* reading a sign depends on the wall it hangs on, not just the paint. *Source:* docs/design-spec.md
- **2026-10-08, design, One token, two values:** design systems give each theme its own value for the same role (`--accent` = yellow in dark, violet in light), because a colour that shines on black can look muddy on white even when it passes contrast. *Analogy:* the same street sign uses reflective paint at night and plain paint by day.
- **2026-10-08, design, Font subsets and lazy font loading:** Google Fonts splits a font into `latin` and `latin-ext` files with `unicode-range`; the browser downloads only the files whose characters appear on the page, and a font that no text uses is never fetched. So English pages skip the Polish file and pages without code skip JetBrains Mono. *Analogy:* a restaurant brings the dessert menu only to tables that ask for dessert.
- **2026-10-08, design, Spotlight with :has():** `.list:has(a:hover) a:not(:hover) { opacity: .32 }` dims every row except the one under the pointer, in pure CSS; gate it with `@media (hover: hover)` and mirror it with `:focus-visible` for keyboards. *Analogy:* a stage light that follows the speaker while the rest of the stage goes dim.
- **2026-10-08, design, Icons need labels:** NN/g's icon research says icons alone are ambiguous; a visible text label (not just a tooltip) makes them findable. That is why the theme switch shows the word LIGHT / DARK next to the eclipse. *Source:* https://www.nngroup.com/articles/icon-usability/
- **2026-10-09, step 0.3, Registrar vs DNS host:** the registrar rents you the name (Cloudflare Registrar, until 2027-10-08); the DNS host answers "where is it?" (Cloudflare DNS). They can be different companies. RDAP shows the public registration data. *Analogy:* the land registry vs the street signs.
- **2026-10-09, step 0.3, A / AAAA / TTL:** A gives an IPv4, AAAA an IPv6 address; TTL 300 lets resolvers cache the answer 5 minutes, so a server move reaches everyone within ~5 minutes. Checked three ways: 1.1.1.1, 8.8.8.8 and the zone's own nameserver. *Analogy:* a phone book entry with a "valid for" date.
- **2026-10-09, step 0.3, Cloudflare proxy (orange cloud):** on by default; DNS then returns Cloudflare's IPs (188.114.x.x) instead of the server's, putting a CDN in front. Turned off (grey, DNS only) per ADR 0005 so Caddy gets its own certificates and real visitor IPs. *Analogy:* a receptionist who takes every call for you.
- **2026-10-09, step 0.3, Negative caching:** a resolver also caches "this record doesn't exist", so a new record can appear later on some resolvers than on others. *Analogy:* a friend who checked yesterday and still believes the shop is closed.
- **2026-10-09, step 0.3, Email authentication:** MX says where mail for the domain goes (lower priority number first); SPF lists who may send; DKIM signs messages; DMARC tells receivers what to do with mail that fails both (`p=reject`). A domain that never sends mail publishes a null MX (`0 .`), `v=spf1 -all` and `p=reject`. *Analogy:* a return address, a wax seal, and a note to the post office to destroy letters without the seal.
- **2026-10-09, step 0.3, SSH host key check (TOFU, out-of-band):** the first SSH connection shows the server's fingerprint; comparing it with the one read on the provider's KVM console proves no one is in the middle before you send a password. A low-res screenshot misread `l` as `1`, which is why you compare against the source. *Analogy:* checking a caller's face on a video call before telling them a secret.
- **2026-10-09, step 0.3, Public key login:** `ssh-copy-id` hangs your public key (a padlock) in `~/.ssh/authorized_keys`; logging in proves you hold the private key without sending it. A stolen padlock opens nothing; the danger is someone writing their own padlock into the file, so sshd refuses loose permissions (`StrictModes`) and SELinux needs the `ssh_home_t` label. *Analogy:* handing the doorman an open padlock only your key fits.
- **2026-10-09, step 0.3, Effective config and drop-in order:** `sshd -T` prints the settings sshd will really use; files in `sshd_config.d/` are read alphabetically and the first value wins, so `01-no-passwords.conf` beats cloud-init's `50-cloud-init.conf`. Test with `sshd -t` before `reload`, then prove it from outside (password login refused, key login works). *Analogy:* the final bill vs the menu.
- **2026-10-09, step 0.3, Bots arrive within hours:** the first failed SSH login came from an unknown IP hours after the VPS went online; internet-wide scanners try every SSH port they find, which is why password logins were turned off the same day. *Analogy:* people trying door handles along a busy street.
- **2026-10-09, step 1.1, baseof + blocks:** `baseof.html` is the shared frame (`<html>`, header, footer); `{{ block "main" . }}` is a hole that each page template (`home.html`, `list.html`, `single.html`) fills with `{{ define "main" }}`. *Analogy:* one picture frame, a different picture per page.
- **2026-10-09, step 1.1, Partials:** `{{ partial "post-meta.html" . }}` pastes a reusable snippet; the `.` hands it the current page, so inside the partial `.Date` means that page's date. *Analogy:* a rubber stamp you ink with whatever page you're on.
- **2026-10-09, step 1.1, Lookup order:** Hugo picks the most specific template that exists (e.g. a section-specific one before `single.html`), so adding a file can change a page without touching the old one. *Analogy:* a waiter checking for a table's special dish before serving the house dish.
- **2026-10-09, step 1.1, .Pages vs site.RegularPages:** `.Pages` is the direct children of the current page (a section's posts, the home page's sections); `site.RegularPages` is every content page on the site, so the home page filters it with `where … "Section" "blog"` to list posts. *Analogy:* the books on one shelf vs the library's whole catalogue.
- **2026-10-09, step 1.1, Dates from git:** with `enableGitInfo`, `.Lastmod` is the date of the last commit touching the file. CI's default checkout is one commit deep, which would make every post "updated today", so CI needs `fetch-depth: 0`. *Analogy:* asking the archive when a document last changed; a photocopy of only today's page can't answer.
- **2026-10-09, step 1.1, Show only what applies:** each meta item appears only when its data exists, and `ne .Params.showUpdated false` treats a missing field as "show" so only an explicit `false` hides it; tested missing / false / true. *Analogy:* automatic headlights with a manual off switch.
- **2026-10-09, step 1.1, Check the evidence before copying a pattern:** reading-time labels are everywhere, but the claimed engagement gains come from marketing anecdotes and none of the exemplar sites use them, so the slot shows "updated" and "tested on" instead. *Analogy:* not buying a gadget just because every shop window has one.
